Sorting Algorithms

Visual step-by-step walkthroughs showing how data moves, not just what the code says. Click any row in the complexity table at the bottom to see real code samples.

Bubble Sort

Bubble sort repeatedly walks through the list, compares neighboring elements, and swaps them if they're in the wrong order. After each full pass, the largest unsorted element "bubbles up" to its correct position at the end. It's the simplest sort to understand but one of the slowest for large data.

↕
Bubble Sort — How It Works
1
Start at the beginning of the list.
2
Compare the current element with the next element.
3
If the current element is larger, swap them. Otherwise, do nothing.
4
Move to the next pair and repeat steps 2–3 until you reach the end.
After this first pass, the largest element is guaranteed to be in its final position at the end of the list.
5
Go back to the beginning and repeat — but now ignore the last element (it's already sorted).
6
Keep repeating until a full pass happens with zero swaps — the list is sorted.
Bubble Sort — Step by Step
Why is it O(n²)? In the worst case (reverse-sorted list), we do n−1 comparisons on the first pass, n−2 on the second, and so on. That sums to (n−1) + (n−2) + … + 1 = n(n−1)/2, which is O(n²). However, if the list is already sorted, we do one pass with zero swaps and stop — that's the O(n) best case.

Merge Sort

Merge sort uses a divide-and-conquer strategy: split the list in half, recursively sort each half, then merge the two sorted halves back together. The merging step is the key — it combines two sorted lists into one sorted list in O(n) time.

⇅
Merge Sort — How It Works
1
If the list has one or zero elements, it's already sorted. Return it.
2
Find the middle of the list and split it into a left half and a right half.
3
Recursively sort the left half using merge sort.
4
Recursively sort the right half using merge sort.
5
Merge the two sorted halves:
Compare the first element of each half. Take the smaller one and place it into the result. Move forward in that half. Repeat until both halves are exhausted.

Why is it O(n log n)? The list is halved at each level of recursion, giving us log₂(n) levels. At each level, the merge step visits every element exactly once — that's O(n) work per level. Total: n × log n. Unlike quicksort, merge sort is always O(n log n), even in the worst case. The trade-off is O(n) extra space for the temporary arrays during merging.

Quick Sort

Quick sort picks a "pivot" element and partitions the array into two groups: elements smaller than the pivot and elements larger. Then it recursively sorts each group. The clever part is that after partitioning, the pivot is in its final correct position — no merging needed.

⚡
Quick Sort — How It Works
1
If the list has one or zero elements, it's already sorted. Return it.
2
Choose a pivot element (commonly the last element, a random element, or the median of three).
3
Partition the remaining elements into two groups:
Walk through each element. If it's smaller than the pivot, place it in the "left" group. If larger, place it in the "right" group. After partitioning, the pivot sits between the two groups — in its final sorted position.
4
Recursively sort the left group (elements smaller than pivot).
5
Recursively sort the right group (elements larger than pivot).

Quick Sort picks a pivot, partitions elements around it, then recursively sorts each side. Average O(n log n) and fastest in practice due to cache-friendly memory access. Worst case O(n²) occurs with bad pivots but is avoidable with randomization.

Insertion Sort O(n)O(n²)O(n²)O(1) Medium

Insertion Sort builds the sorted list one element at a time by inserting each new element into its correct position among the already-sorted elements. Excellent for small or nearly-sorted data. Many real-world sorting implementations (like Python's Timsort) switch to insertion sort for small sub-arrays.

void insertionSort(int[] arr) { for (int i = 1; i < arr.length; i++) { int key = arr[i], j = i - 1; while (j >= 0 && arr[j] > key) { arr[j + 1] = arr[j]; j--; } arr[j + 1] = key; } }

Heap Sort O(n lg n)O(n lg n)O(n lg n)O(1) Fast

Heap Sort builds a max-heap from the data, then repeatedly extracts the maximum element and places it at the end. Guarantees O(n log n) with O(1) extra space — the only comparison sort with both guarantees. Not stable though, and slower in practice than quicksort due to poor cache behavior.

import heapq def heap_sort(arr): heapq.heapify(arr) # build a min-heap in O(n) return [heapq.heappop(arr) # extract min n times → O(n log n) for _ in range(len(arr))]

Searching Algorithms

How to find what you're looking for — from scanning every element to eliminating half at a time.

Linear Search

The simplest search: check every element one by one until you find the target or exhaust the list. No requirements on the data — works on any list, sorted or not.

→
Linear Search — How It Works
1
Start at the first element of the list.
2
Compare it with the target value.
3
If it matches, you're done — return the position.
4
If it doesn't match, move to the next element and repeat.
5
If you reach the end without a match, the target isn't in the list.

Binary Search

Binary search works only on sorted data but is dramatically faster: it eliminates half the remaining elements with each comparison. For a million elements, linear search needs up to 1,000,000 checks — binary search needs at most 20.

½
Binary Search — How It Works
1
Set two boundaries: low at the start and high at the end of the sorted list.
2
Find the middle element between low and high.
3
Compare the middle element with the target:
If it matches → you found it, return the position.
If the target is smaller → it must be in the left half. Move the high boundary to just before the middle.
If the target is larger → it must be in the right half. Move the low boundary to just after the middle.
4
Repeat steps 2–3 with the narrowed range until you find the target or the range becomes empty.
Binary Search — Finding 33 in a Sorted Array
Why is it O(log n)? Each comparison eliminates exactly half the remaining elements. Starting with n elements: after 1 comparison you have n/2, after 2 you have n/4, after k you have n/2ᵏ. You stop when n/2ᵏ = 1, meaning k = log₂(n). For n = 1,000,000 that's just ~20 steps.

Graph Algorithms

BFS and DFS — the two fundamental ways to explore any network of connected nodes.

BFS — Breadth-First Search

BFS explores a graph level by level, like ripples spreading from a stone dropped in water. It visits all neighbors first before moving to the next layer. This makes BFS perfect for finding the shortest path in an unweighted graph.

◎
Breadth-First Search
1
Place the starting node into a queue and mark it as visited.
2
Remove the front node from the queue. Process it.
3
Look at all its unvisited neighbors. Mark each as visited and add them to the back of the queue.
4
Repeat steps 2–3 until the queue is empty.
The queue ensures we process nodes in the order we discovered them — nearest nodes first. This guarantees shortest-path discovery in unweighted graphs.

DFS — Depth-First Search

DFS dives as deep as possible along one path before backtracking. Think of exploring a maze: go straight until you hit a wall, then backtrack to the last intersection and try another path.

↓
Depth-First Search
1
Start at the initial node. Mark it as visited.
2
Pick one unvisited neighbor and move to it. Mark it visited.
3
Repeat step 2 — keep going deeper until there are no unvisited neighbors.
4
Backtrack to the previous node and try its other unvisited neighbors.
5
Repeat until every reachable node has been visited.
DFS can use recursion (the call stack acts as the implicit stack) or an explicit stack data structure. BFS uses a queue; DFS uses a stack — that single difference changes the exploration order entirely.
BFS vs DFS — Quick Decision Guide Need the shortest path? → BFS. Need to explore all possibilities (permutations, paths)? → DFS. Detecting cycles? → DFS. Level-order traversal? → BFS. Topological sort? → DFS.

Dynamic Programming

DP is just "recursion with a notebook" — if you've solved a subproblem before, look it up instead of re-solving it.

When does a problem need DP? It asks for a maximum, minimum, count of ways, or "is it possible" — AND the same subproblem appears multiple times during recursion. If you see overlapping subproblems, that's the signal.
📝
The 5-Step DP Framework (use every time)
1
Define the state — What does dp[i] (or dp[i][j]) represent in plain English?
2
Find the recurrence — How does dp[i] relate to smaller subproblems?
3
Identify base cases — What are the smallest subproblems you can solve directly?
4
Determine iteration order — Fill the table so that dependencies are computed first.
5
Optimize space — Often you only need the previous row, reducing O(n²) space to O(n).

Example: Fibonacci (Why DP Exists)

Computing Fibonacci naively is O(2ⁿ) because the same subproblems are solved over and over. With DP, we store each result and never recompute — O(n).

1D DP dp[i]O(n)Climbing Stairs, House Robber

Climbing Stairs: You can climb 1 or 2 stairs at a time. How many distinct ways to reach stair n? dp[i] = the number of ways to reach stair i. Since you can arrive from stair i−1 (one step) or stair i−2 (two steps), the recurrence is dp[i] = dp[i−1] + dp[i−2] — this is just Fibonacci.

def climb_stairs(n): if n <= 2: return n prev2, prev1 = 1, 2 # base cases: F(1)=1, F(2)=2 for _ in range(3, n + 1): curr = prev1 + prev2 # dp[i] = dp[i-1] + dp[i-2] prev2 = prev1 prev1 = curr return prev1 # Space optimized from O(n) to O(1) — only need last 2 values
Knapsack dp[i] or dp[i][w]O(n × W)Coin Change, Subset Sum

Coin Change: Given coins of different denominations, find the fewest coins to make a target amount. dp[i] = minimum coins to make amount i. For each amount, try every coin: dp[i] = min(dp[i], dp[i − coin] + 1). "If I use this coin, how many more coins do I need for the remainder?"

def coin_change(coins, amount): dp = [float('inf')] * (amount + 1) dp[0] = 0 # base: 0 coins for amount 0 for i in range(1, amount + 1): for coin in coins: if coin <= i: dp[i] = min(dp[i], dp[i - coin] + 1) return dp[amount] if dp[amount] != float('inf') else -1 # coins=[1,3,4], amount=6 → dp=[0,1,2,1,1,2,2] → answer: 2 (3+3)
2D / String DP dp[i][j]O(m × n)Edit Distance, LCS

Longest Common Subsequence: dp[i][j] = LCS length of text1[:i] and text2[:j]. If characters match, we extend from the diagonal: dp[i][j] = dp[i−1][j−1] + 1. If not, take the best of skipping either character: dp[i][j] = max(dp[i−1][j], dp[i][j−1]).

def lcs(text1, text2): m, n = len(text1), len(text2) dp = [[0] * (n + 1) for _ in range(m + 1)] for i in range(1, m + 1): for j in range(1, n + 1): if text1[i-1] == text2[j-1]: dp[i][j] = dp[i-1][j-1] + 1 # match → extend else: dp[i][j] = max(dp[i-1][j], dp[i][j-1]) return dp[m][n]

Stack (LIFO): Push and pop from the top only — both O(1). Used for undo operations, DFS, and expression parsing. Queue (FIFO): Enqueue at back, dequeue from front — both O(1) with a deque. Used for BFS and task scheduling.

# Stack — use a list stack = [] stack.append(1) # push — O(1) stack.append(2) top = stack.pop() # pop — O(1) → 2 # Queue — use deque (list.pop(0) is O(n)!) from collections import deque q = deque() q.append(1) # enqueue — O(1) q.append(2) front = q.popleft() # dequeue — O(1) → 1
